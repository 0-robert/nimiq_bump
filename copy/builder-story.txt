I wanted to find out what you can build when a payment costs nothing and lands in a second, because that changes what money can be used for. It stops being something you send occasionally and becomes something you can spend like tapping a button. So I built the smallest thing I could think of where every single action is a transaction.

The part that took the longest was settlement, and it is the part I would want someone to look at.

Nimiq is marketed on one second transactions. That figure is inclusion, not finality. A micro block comes from a single validator and can be reorganised up to 59 blocks deep. The macro block closing each batch is what finalises it, and that is anywhere from zero to sixty seconds out. Albatross also writes failed transactions to the chain with the fee charged and the effect thrown away, so a transaction existing proves nothing on its own.

I did not want to pick between a screen that feels dead for half a minute and a server that believes whatever it is told. The slot changes hands as soon as the payment is included, and says on its face that it is still settling until a macro block confirms it. Before that the server checks the execution result, the recipient, the value, the network, the memo and a full batch of confirmations. If a reorg ever undid one, the slot would go back.

Two other things worth knowing. The provider has no sender parameter, so the wallet picks its own signing account and it is not necessarily the one on screen. Everything is reconciled by recipient and memo instead. And a declined payment comes back two different ways, sometimes thrown and sometimes resolved as an error object, which is an open bug. Handling only one of them means a refusal reads as a successful payment, so both paths go through the same function and nine of the tests cover it.

The whole slot is one Durable Object. They run single threaded, so two people bumping in the same second are put in order by the platform and the race cannot happen rather than being defended against.
